# 일본 맛집 숏츠 지도

맛집 숏츠 보다가 저장해 둔 일본 가게들을 지도에 꽂아 둔 개인 프로젝트입니다. 영문 보조명은 **Japan Shorts Food Map**입니다.

This project is a static React/Vite site deployed for free on GitHub Pages at `https://lowbyyj.github.io/my-yt-japan-restaurant/`. It builds a Leaflet map from generated JSON at `public/data/places.json`. There is no backend server, database, paid hosting, Google Maps JavaScript API, or Google Places API.

## Principle

dr.lowb is the product director and final tester, not the data-entry operator. Real restaurant/shop records must not be manually curated. Production place data must be generated by the automated YouTube ingestion, extraction, geocoding, and public-data build scripts.

Tiny synthetic fixtures are allowed only for tests and empty-state behavior. They must not be presented as real production data.

## Local Setup

```bash
npm install
npm run dev
```

On Windows PowerShell, use `npm.cmd` if script execution policy blocks `npm.ps1`:

```powershell
npm.cmd install
npm.cmd run dev
```

## Data Ingestion

Create a local `.env` or set environment variables without committing secrets:

```bash
YOUTUBE_API_KEY=***
YOUTUBE_CHANNEL_HANDLE=@space_tamnik
MAX_VIDEOS=100
GEOCODE_PROVIDER=nominatim
```

Then run:

```bash
npm run data:all
```

For no-key readiness checks that never call YouTube or Nominatim:

```bash
npm run data:doctor
npm run data:dry-run
```

The pipeline:

1. `ingest:youtube` resolves the channel with YouTube Data API, scans recent uploads, filters likely Shorts, and retrieves top-level comments.
2. `extract:places` ranks owner-authored comment candidates and extracts place/address/map signals.
3. `geocode:places` first parses coordinates from Google Maps URLs, then uses respectful cached Nominatim fallback for unresolved candidates.
4. `build:data` writes sanitized public records to `public/data/places.json`, merges vetted agent-assisted entries from `data/location_resolutions.json` when they match an automated YouTube candidate, and applies public-safe display copy from `data/place_enrichments.json`.
5. `validate:data` validates the public JSON with Zod.

If `YOUTUBE_API_KEY` is missing, the scripts do not fabricate data. They keep `public/data/places.json` as an empty array and write `public/data/data_status.json` with `dataGenerated: false`.

`data:doctor` checks local readiness, ignored raw/cache paths, public JSON validation, Vite base path, and secret presence without printing secret values. `data:dry-run` exercises parser/publish-gate behavior with synthetic fake fixtures only. `data:all` is the real ingestion path and should only be run when `YOUTUBE_API_KEY` is provided through the environment.

## Source Data Caveat

The YouTube Data API does not provide a guaranteed pinned-comment field in the implemented flow. This project therefore does not claim that the API confirmed a comment is pinned. It detects `owner_location_comment_candidate` records by preferring top-level comments authored by the channel owner, `commentThreads.list` relevance order, fallback time order, and place/address/map text signals.

## Deployment

The site is deployed from this repository to free GitHub Pages with GitHub Actions:

```text
https://lowbyyj.github.io/my-yt-japan-restaurant/
```

M3 uses the `gh-pages` branch as the Pages source because the current GitHub OAuth token lacks the `workflow` scope required to push workflow files. The local deployment flow still validates data, runs tests, builds `dist/`, and publishes only the static build output to `gh-pages`. M3 does not modify the separate `lowbyyj.github.io` personal homepage repository; M4 can add a homepage link later.

## Google Maps

Google Maps links are used only as outbound URLs. The site does not use the Google Maps JavaScript API or Google Places API. Coordinates are parsed from public Google Maps URL forms when present; otherwise Nominatim may be used as a small, cached, one-time geocoding fallback.

## Agent-Assisted Location Resolutions

`data/location_resolutions.json` is a public-safe bridge for cases where the automated owner-comment candidate clearly names a Japan place but automated geocoding only produced a search URL. Each resolution must match an existing generated candidate by video/comment, include public evidence URLs, avoid paid Google Places data or Google Maps scraping as the coordinate source, and keep unresolved or ambiguous branches out of `places.json`.

`data/place_enrichments.json` stores optional public-safe Korean display copy for published places. The public UI uses `displayDescriptionKo`, `placeTypeKo`, `signatureKo`, and `whyKo` when present, while preserving generated fallback text when enrichment is absent. M3.3 bulk marker expansion uses Japan GSI public address search as a public/free coordinate source for exact owner-comment addresses, raising the public map to 75 enriched markers without paid Google APIs or direct `places.json` editing. M3.4 keeps the same source constraints, rewrites public descriptions to user-facing copy, simplifies genre filters to `밥`/`디저트`/`술`, starts the map on Tokyo, and expands the public map to 158 enriched markers.

## Public Positioning

The public site is presented as a personal map for saved Japan food Shorts. Source videos remain available through each card's video link, while the page title, metadata, and user-facing copy stay channel-neutral.
