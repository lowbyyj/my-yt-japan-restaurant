# space-tamnik-japan-map

Unofficial auto-generated Japan map of places from `@space_tamnik` Shorts owner comment candidates.

This project is a static GitHub Pages-friendly React/Vite site. It builds a Leaflet map from generated JSON at `public/data/places.json`. There is no backend server, database, paid hosting, Google Maps JavaScript API, or Google Places API.

## Principle

Dr. Low is the product director and final tester, not the data-entry operator. Real restaurant/shop records must not be manually curated. Production place data must be generated by the automated YouTube ingestion, extraction, geocoding, and public-data build scripts.

Tiny synthetic fixtures are allowed only for tests and empty-state behavior. They must not be presented as real `@space_tamnik` data.

## Local Setup

```bash
npm install
npm run dev
```

On Windows PowerShell, use `npm.cmd` if script execution policy blocks `npm.ps1`:

```powershell
npm.cmd install
npm.cmd run dev
```

## Data Ingestion

Create a local `.env` or set environment variables without committing secrets:

```bash
YOUTUBE_API_KEY=your_key
YOUTUBE_CHANNEL_HANDLE=@space_tamnik
MAX_VIDEOS=100
GEOCODE_PROVIDER=nominatim
```

Then run:

```bash
npm run data:all
```

The pipeline:

1. `ingest:youtube` resolves the channel with YouTube Data API, scans recent uploads, filters likely Shorts, and retrieves top-level comments.
2. `extract:places` ranks owner-authored comment candidates and extracts place/address/map signals.
3. `geocode:places` first parses coordinates from Google Maps URLs, then uses respectful cached Nominatim fallback for unresolved candidates.
4. `build:data` writes sanitized public records to `public/data/places.json`.
5. `validate:data` validates the public JSON with Zod.

If `YOUTUBE_API_KEY` is missing, the scripts do not fabricate data. They keep `public/data/places.json` as an empty array and write `public/data/data_status.json` with `dataGenerated: false`.

## Owner Comment Candidate Caveat

The YouTube Data API does not provide a guaranteed pinned-comment field in the implemented flow. This project therefore does not claim that the API confirmed a comment is pinned. It detects `owner_location_comment_candidate` records by preferring top-level comments authored by the channel owner, `commentThreads.list` relevance order, fallback time order, and place/address/map text signals.

## Build

```bash
npm run test
npm run validate:data
npm run build
```

## Google Maps

Google Maps links are used only as outbound URLs. The site does not use the Google Maps JavaScript API or Google Places API. Coordinates are parsed from public Google Maps URL forms when present; otherwise Nominatim may be used as a small, cached, one-time geocoding fallback.
